Domain 1: Multi-Cloud Publish Portal & Direct Server Uploads

Target Hosting: GoDaddy cPanel, Vercel, Railway, Custom Domain DNS

High Technical Gap
📌 What Was Requested
"Under deployment folder need to publish static HTMLs and backend API related file with MySQL... and future add custom domain and upload FTP / GitHub via this application to authenticate particular deployment server."
✅ What Was Delivered in Main
  • Multi-cloud deployment package exporter (/api/publish/export).
  • Bundles complete static storefront HTMLs, CSS, and assets into .zip.
  • Pre-generates both PostgreSQL (schema.postgres.sql) and MySQL (schema.mysql.sql) database seeds.
⚠️ The Specific Gaps Identified
  • No Direct In-App FTP/SFTP Client: Currently, the user receives a downloadable ZIP or local deployment folder. There is no in-app FTP transport engine (e.g. basic-ftp) allowing users to enter GoDaddy FTP Host, Username, and Password to push files directly to their hosting server.
  • No Automated GitHub API OAuth/PAT Push: The user requested pushing to GitHub via the app. There is currently no GitHub REST API integration to automatically create and commit to a remote repo from the Publish Portal.
  • GoDaddy cPanel Node.js Wrapper: GoDaddy cPanel requires an app.js entry point and .htaccess rewrite rules for Phusion Passenger. The current export bundles standard Express api/server.js.
  • Custom Domain DNS & SSL: Custom domain input is saved as text, but lacks automated CNAME verification polling or SSL certificate check.
🗄️

Domain 2: Database Migration Tracking & Multi-Engine Dialects

PostgreSQL vs MySQL Dialects, Step-by-Step Execution, and Rollbacks

Medium Gap
📌 What Was Requested
"Upgrade an existing database (DB migration only) - I don't know what database is last migrated and wanted to know the status and which version are not yet migrated pending status so need another columns so that I can migrate one by one from last done... if API deployment select MySQL or Postgres."
✅ What Was Delivered in Main
  • Tracking schema: Added version, migration_name, status, batch, execution_time_ms, sql_preview, error_message to zkc_pg_migrations.
  • CLI: npm run db:status, npm run db:step, npm run db:migrate.
  • Web Dashboard: Interactive merchant/db-migrations.html with live step button.
  • All 8 versions (v1.0.1 to v1.0.8) verified in PostgreSQL.
⚠️ The Specific Gaps Identified
  • MySQL Migration Runner: api/services/db-migrator.js currently hardcodes PostgreSQL client (const { Client } = require('pg')). If a client deploys using MySQL on GoDaddy, the migrator service needs a mysql2 connection adapter and MySQL DDL syntax.
  • Rollback / Down Migration Capability: The system has forward step execution (migrateNextStep()), but lacks a rollback step (db:rollback) to revert the last applied batch if a deployment needs to be stepped down.

Domain 3: Merchant Admin Experience ("Shopify / WordPress Model")

Unified Visual Section Editor vs Separate Standalone Tools

Medium Gap
📌 What Was Requested
"When new client onboarded at first time... need like Shopify model in client admin merchant / dashboard they can add/edit like store builder in merchant side... so in merchant side need add category/pages/themes like WordPress like Shopify model."
✅ What Was Delivered in Main
  • Merchant side has dedicated sections: products.html, categories.html, pages.html, themes.html, and inventory.html.
  • Stock quantity added to add/edit product modal across both portals.
  • Theme Customizer view allows preset theme switching.
⚠️ The Specific Gaps Identified

In ZKCommerce, /store-builder/ is a separate application route, while merchant admin uses traditional form tables.
