How store URL works after creation

Step 1: Merchant completes setup wizard → POST /api/stores → returns store.slug
Step 2: app.js detects environment (file://, localhost, .vercel.app, .railway.app, or custom domain)
Step 3: getStoreURL(slug) returns the correct URL for that environment
Step 4: "View My Store" button opens the URL in a new tab
Step 5: Storefront page reads ?store=slug from URL → fetches GET /api/storefront/slug

For local dev: Open storefront/home.html?store=rajanTextiles in browser — loads demo store from local API
For Vercel: Same page, same URL format. The API_BASE auto-detects and points to Railway API.

Exact steps to fix Railway right now

1. Replace Dockerfile in your GitHub repo with the new one (no .env.example copy)
2. Replace railway.toml in your GitHub repo with the fixed version
3. In Railway dashboard → your service → Variables → add:
   DATABASE_URL = your Neon production URL
   JWT_SECRET = your JWT secret from .env
   PORT = 3000
   NODE_ENV = production
4. Push to GitHub → Railway auto-redeploys → should pass
5. In Railway → Settings → Networking → Generate Domain → this gives you your API URL
6. In Vercel → Settings → Environment Variables → add RAILWAY_API_URL = https://your-api.railway.app/api
