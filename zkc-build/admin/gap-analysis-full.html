Backend audit — API, database, infrastructure
Detailed review of server.js, phase2-routes.js, all SQL files, and infrastructure gaps

✅ What's built in the backend

✅
Database schema — 27 tables across 3 SQL files. Multi-tenant, multi-warehouse, variants, loyalty, campaigns. Production-quality design.
✅
JWT authentication middleware — verifyToken, requireRole written. Just not applied to routes.
✅
6 live API routes — /health, /api/categories, /api/search, /api/shipping/estimate, /api/orders/:id/invoice (x2)
✅
Razorpay integration stub — Instance created, webhook signature verification written
✅
Multer file upload config — S3 storage engine configured, file type + size validation done
✅
GST calculation logic — split(), gstr1Export() functions written with real GSTIN validation
✅
Nodemailer email setup — Transporter configured, welcome + order email templates exist

❌ Critical backend gaps

❌
34+ API routes missing — Auth routes, product CRUD, order management, cart, loyalty, campaigns all not wired. phase2-routes.js has 0 routes.
❌
No input validation middleware — No Joi/Zod schemas. SQL injection possible. No rate limiting beyond basic express-rate-limit stub.
❌
No database indexes — Schema has no CREATE INDEX statements. Full table scans on orders, products at scale = slow queries.
❌
No Row Level Security — PostgreSQL RLS policies not set. One merchant could theoretically access another's data.
❌
No Razorpay payout routes — Payment collection works but payout to merchant bank accounts not implemented.
❌
No background job system — Email, WhatsApp, labels, GSTR-1 all run synchronously. Will timeout under load.
❌
No Redis caching — Every page load hits Postgres. Product listings, categories, storefront homepage need cache.
