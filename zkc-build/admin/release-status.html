Blockers — must fix before staging
🔐

1. login.html still has demo fallback — CRITICAL

The file contains demo_token and bypasses the real API. The POST /api/auth/login route is fully written in server.js. Fix: remove the demo fallback block in login.html and wire the form's submit handler to call the API endpoint.

💳

2. Razorpay SDK not loaded in checkout.html — CRITICAL

The checkout page shows "Place Order" which triggers a toast. The routes POST /api/payments/razorpay/order and POST /api/payments/razorpay/verify are fully written. Fix: add the Razorpay checkout.js script tag, call the order API, open the Razorpay modal, call verify on success, redirect to payment-success.html.

🗄️

3. phase3-additions.sql not yet run — CRITICAL

The SQL file (385 lines) adds 9 new tables (returns, payouts, store_staff, audit_log, etc.), 25 indexes, and Row Level Security on 13 tables. Without this the API will throw errors on returns, payouts, and staff routes. Fix: run psql $DATABASE_URL -f database/phase3-additions.sql after setting up Neon.

🌐

4. 45 frontend pages not wired to API — HIGH

Every merchant dashboard page (products, orders, analytics, campaigns, inventory, etc.) currently shows hardcoded demo data and buttons that fire toasts. Each page needs its data-fetch and form-submit handlers wired to the corresponding API routes. Priority order: auth → products → orders → payments → analytics → rest.

📦

5. npm packages not installed — CRITICAL for API

The API requires bcryptjs, zod, razorpay, jsonwebtoken, express-rate-limit, helmet, multer, nodemailer, passport. Run npm install in the project root before attempting to start the server.

🔑

6. Razorpay live keys — PRODUCTION ONLY

Apply for Razorpay live account KYC (2–3 business days). For staging, test keys are sufficient. Once KYC is done, swap RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET in Railway environment variables.

📱

7. Gupshup WhatsApp not configured — HIGH

The whatsapp.js module is fully coded with 6 message types. Only GUPSHUP_API_KEY env var is missing. Register at gupshup.io, create WhatsApp Business app, get API key, add to Railway env vars. Template approval takes 24–48 hours.

Exact deployment steps
Do these in order. Staging first, then production.
Phase A — Do today (no code changes needed)
1

Push HTML to Vercel for demo URL

Push repo to GitHub. Connect to Vercel. Deploy. You get a live demo URL in 2 minutes. This is the investor/pilot merchant demo — all pages look real.

2

Create Neon database

Sign up at neon.tech → New project → Region: ap-south-1. Run: npm run db:migrate (runs all 4 SQL files). Copy connection string to use in step 4.

3

Apply for Razorpay test account

razorpay.com → sign up → KYC takes 2–3 days. Get test keys immediately for development. This starts the clock on live key approval.

4

Deploy API to Railway

railway.app → New project → Deploy from GitHub → select repo. Add all env vars from .env.example: DATABASE_URL (Neon), JWT_SECRET, RAZORPAY_KEY_ID (test keys). API goes live at Railway URL in 2 minutes.

Phase B — Week 1 (frontend wiring)
5

Wire login.html → real API

Remove demo_token fallback. Replace with fetch('/api/auth/login', {method:'POST', body:JSON.stringify({email,password})}). Store JWT in localStorage. Redirect by role. Estimated: 30 minutes.

6

Wire checkout.html → Razorpay

Add <script src="https://checkout.razorpay.com/v1/checkout.js"></script>. Call POST /api/payments/razorpay/order to get order ID. Open Razorpay modal. On success call POST /api/payments/razorpay/verify. Redirect to payment-success.html. Estimated: 2 hours.

7

Wire merchant dashboard pages

Priority: products-add → orders → analytics → inventory. Each page: replace hardcoded data with fetch(API_URL + '/api/...') on load. Replace toast buttons with real API calls. Estimated: 3–5 days for all merchant pages.

8

Configure Cloudflare R2 for images

Create R2 bucket in Cloudflare dashboard. Add R2_ACCESS_KEY, R2_SECRET_KEY, R2_BUCKET to Railway env vars. Product image upload will then work end-to-end via the Multer middleware already in server.js.

Phase C — Week 2 (services + go-live)
9

Configure Gupshup WhatsApp

Add GUPSHUP_API_KEY to Railway. Submit 3 message templates (order confirmed, shipped, COD OTP) for Meta approval. Takes 24–48h. Test with a real phone number.

10

Set up Cloudflare DNS + Worker

Add zkcommerce.in to Cloudflare. Deploy deploy/cloudflare-worker.js to Cloudflare Workers. Add wildcard CNAME *.zkcommerce.in → Worker. Merchant storefronts will then be live at merchant.zkcommerce.in.

11

End-to-end test — full purchase flow

Register merchant → set up store → add product → customer registers → adds to cart → checks out → UPI payment → order confirmed → merchant dispatches → customer tracks. All 12 steps must complete without errors.

12

Onboard 5 pilot merchants (Tamil Nadu)

Share Vercel demo URL. Give them Growth plan free for 60 days. Get real product data, real orders. Fix any issues that surface. This is your staging environment with real usage.

Phase D — Production launch
13

Swap Razorpay live keys

After KYC is approved: update RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET in Railway to live values. Add webhook URL: https://api.zkcommerce.in/api/payments/webhook in Razorpay dashboard.

14

Security audit + load test

Run OWASP ZAP scan on the API. Load test with k6 or Artillery: 100 concurrent checkouts. Fix any issues. Set up Sentry DSN in Railway env vars for error monitoring.

15

Production launch 🚀

Point zkcommerce.in to Vercel. Point api.zkcommerce.in to Railway. Send invites to first batch of merchants. Monitor Sentry for errors. Monitor Railway for CPU/memory. You are live.
